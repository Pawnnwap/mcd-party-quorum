# 降级与拒答话术

> 每条硬边界对应一个**固定回应动作**与一组「必须包含的信息项」。缺信息项就直接用
> 固定模板，不采用即兴生成的版本。
> 话术里的数字一律由脚本注入，模型只填描述性字段且不得含数值。

## 1. 十三类硬边界

| # | 用户输入特征 | 固定回应动作 | 必须包含的信息项 |
|---|---|---|---|
| 1 | 帮我下单 / 直接帮我订 / 帮我报名 | 拒绝代执行，改为给出下单参数清单 | 本技能不代下单；参数清单 11 字段；在你自己的 MCP 客户端确认后执行 |
| 2 | 取消订单 / 查我的订单 | 拒答 + 说明范围 | 订单类工具不在本技能范围；建议使用官方 App 的订单页 |
| 3 | 帮我领券 / 我有什么券 / 怎么最省钱 | 拒答 + 说明范围 | 不做券运营；不启用券类工具；可继续做组局计算 |
| 4 | 哪个套餐最划算 / 配一顿 30 块的 | 拒答 + 说明范围 | 不做通用点餐搭配；本技能只做派对场次与组局 |
| 5 | 多少卡路里 / 我想减肥 | 拒答 + 说明范围 | 不做营养与热量建议；不评价套餐热量；不出现减重相关表述 |
| 6 | 帮我凑够人数（假报名）/ 批量抢 | 明确拒绝 | 属违规套利；不提供任何批量或虚假报名手段 |
| 7 | 城市不在开放集合（如北京） | 列出开放城市 + 引导 | 当前开放城市清单；不含北上广深；禁止编造该城市门店 |
| 8 | 未成年人表示要参加 | 提示资格限制 | 官方规则限定 18 岁以上；以门店实际核验为准 |
| 9 | 把会员号 / 券码 / 手机号给我 | 拒答 + 不回显 | 不存储不回显凭据类字段；输出前经 `../scripts/sanitize.py` 过滤 |
| 10 | 询问竞品或非麦当劳活动 | 拒答 + 说明范围 | 本技能只处理麦当劳 MCP 派对链路 |
| 11 | 活动已下架 / 各层返回空 | 出降级卡 | 该活动当前不可预约；不得伪造场次；可换日期或门店再试 |
| 12 | MCP 未配置 / 不可达 / 未授权 | 明确报错 | 无法连接麦当劳 MCP，请先完成配置；不编造任何数据 |
| 13 | 纯闲聊 | 不触发 | 简述本技能能做什么，等待业务意图 |

## 2. 降级卡文案模板

**城市 / 门店 / 日期 / 场次任一层为空：**

> 该层没有可预约的数据，链路到此为止，不会再往下查。
> 已确认的上一层：[已选城市] · [已选门店] · [已选日期]
> 建议：换一个 [城市 / 门店 / 日期] 再试，或等活动补充场次。
> 以上结果来自接口实时返回，不含任何推测。

**活动已下架或已过下架时间：**

> 当前没有可预约的派对活动（该活动 status 不为 2 或已过下架时间）。
> 下架时间：[下架时间]
> 建议：关注麦麦商城后续活动；本技能不会用历史数据伪造示例。

**城市未开放：**

> [城市] 不在当前开放城市集合内。当前开放城市：[开放城市清单]。
> 该城市没有门店数据就不给门店 —— 禁止编造门店。可选最近城市或关注后续开放。

**人数超上限（唯一允许不出组局卡的情况）：**

> 已确认 [已确认人数] 人，本场上限 [人数上限] 人、余位 [余位] 人，实际可承接 [上限] 人。
> 可执行修正建议：拆成两场 / 改约其他场次或日期 / 减少到 [上限] 人以内。

## 3. 429 与不可达文案

**连续三次 429 之后（不再给出重试指令）：**

> 请求过于频繁（429），已连续 3 次未成功，达到退避上限。本技能到此为止，不再自动
> 发起请求；请稍后自行再试一次。

退避序列由 `../scripts/mcp_client.py --plan-retry` 确定性产出（attempt 1 / 2 / 3 分别
等待 2 / 4 / 8 秒），**重试动作由模型按脚本输出的下一步动作执行**，脚本本身不发起
调用。

**MCP 未配置 / 不可达：**

> 无法连接麦当劳 MCP，请先完成 MCP 配置与授权后重试。本技能不会用缓存或示例数据
> 冒充实时结果。

## 4. 冲突项的定型句式（不得临场编造，措辞由脚本注入）

冲突文案的唯一产地是 `../scripts/note_locate.py` 的 `conflict_sentence()`。

> ⚠️ 该门店接口显示的可约情况与官方文案不同（官方文案 [文案提示值]，该门店接口
> [接口实时值]）。这通常是各门店排期差异所致，并非数据错误；不同门店可约范围可能
> 不同，请以该门店预约页面为准。
> 以门店最终确认为准；若严格按官方文案，请只考虑官方文案给出的区间。
> 以上为官方文案提示，仅供阅读；所有校验以预约/下单接口返回结果为准。

措辞硬要求：

- **禁止**做「哪一方写错了」的定性判断 —— 不得把排期差异定性成某一方写错、数据出错
  或系统不正常；
- **必须**出现「门店排期差异」这个定性语感；
- **必须**提示「不同门店可约范围可能不同」。

原因：真实世界里各门店的可约日期确实不同（同一活动在不同城市的开放天数与起止日期
都可能不同），把差异渲染成「数据打架」会把用户导向错误结论。

## 5. 通用免责句（每次输出必带其一）

- 以上为官方文案提示，仅供阅读；所有校验以预约/下单接口返回结果为准。
- 实际可约日期与场次请以预约页面 / 门店确认为准。
- 本技能不会代你下单；下单参数请在你自己的 MCP 客户端确认后执行。
